1. Introduction

1.1 Purpose

The purpose of this Software Requirements Specification (SRS) document is to provide a complete, rigorous, and unambiguous technical specification for CareConnect360, a cloud-enabled, full-stack telemedicine and clinical management platform. This specification conforms to the IEEE Std 830-1998 standard and establishes binding functional, performance, security, and interface baselines for academic lab evaluations, faculty reviews, and production deployment.

1.2 Scope of the System

Healthcare accessibility is frequently hindered by geographic isolation, long outpatient waiting queues, fragmented paper records, and accidental adverse drug interactions. CareConnect360 resolves these bottlenecks through a browser-native clinical consultation hub:

  • Dynamic Doctor-Patient Matchmaking: Multi-criteria search by medical specialty (Cardiology, Dermatology, Pediatrics, General Medicine), consultation fee, and real-time slot reservation without double-booking.
  • Native WebRTC Audio/Video Teleconsultation: Zero-install, peer-to-peer (P2P) HD audio/video consultation with microphone mute/unmute, camera toggle, screen sharing, PIP feed swapping, and dynamic watermark sync.
  • Clinical Decision Support System (CDSS): Real-time drug contraindication radar cross-checking prescribed medications against patient known allergies (e.g. Penicillin, NSAIDs).
  • Digitally Signed e-Prescriptions: Client-side cryptographic signature rendering and instant verifiable PDF downloads via jsPDF with QR verification codes.
  • Electronic Health Records (EHR) Vault: Centralized timeline logging patient vitals telemetry (BP, SpO2, Heart Rate) and diagnostic lab reports (.pdf, .png, .jpg).

2. Overall Description

2.1 Product Perspective

CareConnect360 operates as an autonomous, multi-tier web application built upon modern decoupled architecture, combining an HTML5/CSS3/ES6 presentation tier, a Node.js/Express.js application tier, a `/peerjs` WebRTC signaling engine, and cloud/local persistence.

2.2 User Roles & Characteristics

User Persona Technical Skill Core Privileges & Responsibilities
Patient Novice to Intermediate Register, browse verified specialist directory, book consultation appointments, join encrypted video room, upload lab reports, view vital trends, and download signed e-Prescriptions.
Doctor / Specialist Intermediate Manage OPD schedule, review patient intake vitals & diagnostic history, conduct P2P video consultation, author prescriptions with CDSS contraindication alerts, and digitally sign prescriptions.
Administrator High (DevOps) Monitor system uptime, manage doctor verification credentials, view platform audit logs, enforce data privacy compliance, and moderate user accounts.

5. Non-Functional Requirements (NFRs)

Attribute Target Benchmark Testing & Verification Protocol
5.1 Performance Initial load < 1.8s; WebRTC stream latency < 200ms; REST API latency < 150ms. JMeter load testing under 50 concurrent simulated users.
5.2 Security Salted Bcrypt password hashing (10 rounds); DTLS-SRTP 256-bit media stream encryption. OWASP ZAP vulnerability scanning and automated penetration testing.
5.3 Reliability Uptime ≥ 99.0%; automatic session recovery on ICE candidate timeout. Stress testing with simulated network drops.
5.4 Portability Chrome (v100+), Edge (v100+), Firefox (v98+), Safari (v15+); responsive mobile viewports. Cross-browser testing across mobile and desktop display viewports.
